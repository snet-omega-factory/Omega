**FR**
- R7-FR1: it returns `(running provider, premium_model)` when any normalised keyword token
  occurs in the normalised text, **or** the user-plus-tool message count in this request is
  `>=` `router_escalate_items`. Otherwise `(running provider, configured model)`.
- R7-FR2: keywords are normalised at startup with `llmRequestContentsNormalized`'s own
  transformation (lowercase, `[](),.:`→space), and logged in that form. A keyword that
  normalises to empty, or to more than one token, fails startup with its name. Otherwise it
  silently never matches, which is O7's defect.
- R7-FR3: matching is **whole-token**, as #373 does (the split on spaces). `errors` does not
  match `error`. If the architect wants substring matching, that's a change of intent: say so
  and E changes.
- R7-FR4: the documented defaults in `config/config.yaml`, the setup script's prompt text and
  the README name the same keywords and threshold, from one source (spec §10).
- R7-FR5: `llmRequestContentsNormalized` is unchanged from #373 and gets its first test.

**T**
