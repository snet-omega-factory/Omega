# Tickets addendum 1: R1-FR3 and R1-T3

**Why.** As written, R1-FR3 ("no code outside `lib_llm_ext.py` reads `_client`") also forbids
`OpenAIProviderImpl` using its **own** lazy client (`openai.py:144-152` @ 030c0144). That is an
`AIProvider` subclass touching `self._client`, which is legitimate and out of R1's scope. The
defect R1 targets is #373's reach into **another object's** private state:
`openrouter.py:29` @ 193e9f58, `delegate._client`. My wording was too broad, so I'm correcting
it here.

**R1-FR3 (replaces).** Outside `lib_llm_ext.py`, no code reads `_client` on any object other
than `self`.

**R1-T3 (replaces).** An AST test over `providers/`:
- **Flagged:** an attribute read of `_client` whose receiver is not the bare name `self`, and
  `getattr(<x>, "_client")` where `<x>` is not `self`.
- **Fixtures:**
  - `providers/` @ 193e9f58 → flagged at `openrouter.py:29`.
  - @ 030c0144 → passes, including `openai.py:144-152`.
  - A `getattr(delegate, "_client")` fixture → flagged.
- **Docstring:** states the exception (a subclass may use its own `self._client`) and that it
  doesn't follow aliasing (`c = self; other = c.delegate`).

Everything else in R1 is unchanged.

**Evidence grade, restated for all tickets.** A run in a local shim with stubbed modules (no
`tests/pytest.sh`, no Omega runtime) is reported as **"run in shim, stubs named"**. It is
evidence of the test logic, not a pass in the agreed venue. The bundle should list which modules
were stubbed.
