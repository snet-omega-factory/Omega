### Functional requirements

- R4-FR1 **the mock records every request, not just the last.** One test sends a user
  message, then the agent runs **further iterations**: the tool round-trip, then the
  `[NO NEW USER INPUT…]` autonomous turn (`loop.metta`, `$lastmessage`). So "the last request"
  is the wrong request for A3 and A4b. The new RPC verb `requests_since(marker)` returns, in
  order, one record per `chat()` call: `{seq, user_text, provider, model, router, n_messages}`.
  `user_text` has the `Step …: ` prefix already stripped by `_STEP_PREFIX`. A companion verb
  `mark()` returns the current `seq`.
- R4-FR2 **the mock records refusals too:** when the agent refuses an envelope (A5), there is
  **no** `chat()` call. Tests assert the absence: no record between the markers with that
  `user_text`.
- R4-FR3 **one agent start per configuration.** `Autotests/mock/conftest.py` keeps **one**
  agent and **one** controller per pytest session (session-scoped `llm` fixture), so this
  means one **pytest invocation per configuration**, not a per-test fixture. Four
  configurations:

  | Config | `model` | `premium_model` | `router` | keywords / items |
  |---|---|---|---|---|
  | `off` | `econ-1` | unset | unset | — |
  | `default` | `econ-1` | `prem-1` | `default` | `["zzkeyword", "error"]` / `4` |
  | `testrouter` | `econ-1` | `prem-1` | `qa_fixed` | — |
  | `bad` | `econ-1` | `prem-1` | `defualt` | — |

  Plus startup-only cases that never run the loop: `router: default` with `premium_model`
  unset.

  The `default` config sets **its own** keywords and threshold on purpose, so expected values
  come from the test's setup. `zzkeyword` cannot occur by accident. The documented defaults are
  tested separately (R7-T5).
- R4-FR4 **the test router `qa_fixed`** lives under `routers/` and registers through
  `config/plugins.yaml` only. It returns, chosen by the user text it sees:
  - `qa-other-provider` → `(OtherProvider, econ-1)`
  - `qa-not-permitted` → `(Test, not-permitted)`
  - `qa-raise` → raises
  - `qa-malformed` → a non-pair
  - anything else → `(Test, prem-1)`

  The diff that adds it touches nothing under `src/` or `providers/`. That diff **is** A7's
  evidence.
- R4-FR5 **the existing mock suite (~45 `test_*_mock.py`) runs under config `off` unchanged
  and stays green.** That is the widest evidence for default-off (invariant 7) that we have, at
  no cost.

### Behaviours (Gherkin, replacing spec §6's; see Q2)

```gherkin
Feature: LLM model routing

  Background:
    Given the agent runs on the mock provider "Test"

  # config: off
  Scenario: routing off sends the configured model
    Given the agent is configured with model "econ-1" and no router
    When the user sends "what is the time"
    Then the request for "what is the time" is sent to model "econ-1"

  # config: default
  Scenario: a clean request uses the economy model
    Given the agent is configured with model "econ-1", premium model "prem-1", router "default",
      escalation keywords "zzkeyword, error" and an item threshold of 4
    When the user sends "what is the time"
    Then the request for "what is the time" is sent to model "econ-1"

  Scenario: the user's keyword escalates
    Given the same configuration
    When the user sends "please use zzkeyword now"
    Then the request for "please use zzkeyword now" is sent to model "prem-1"

  Scenario: a failed tool call escalates the next request, and only that one
    Given the same configuration
    And the model answers "run broken script" with a tool call that fails
    When the user sends "run broken script"
    Then the request that carries the failed tool result is sent to model "prem-1"
    And the first request after it with no failure in its own messages is sent to model "econ-1"

  Scenario: many tool results in one request escalate
    Given the same configuration
    And the model answers "do four things" with four successful tool calls
    When the user sends "do four things"
    Then the request that carries those four tool results is sent to model "prem-1"

  Scenario: a model the agent already named is kept
    Given the same configuration
    When the agent sends a request that names model "econ-1" and contains "zzkeyword"
    Then that request is sent to model "econ-1"

  # config: testrouter
  Scenario Outline: a router's bad answer never reaches an endpoint
    Given the agent is configured with router "qa_fixed"
    When the user sends "<text>"
    Then no request for "<text>" reaches the provider
    And the log names "<logged>"
    And the agent answers the next message normally

    Examples:
      | text               | logged                     |
      | qa-not-permitted   | Test not-permitted         |
      | qa-other-provider  | OtherProvider econ-1       |
      | qa-raise           | qa_fixed                   |
      | qa-malformed       | qa_fixed                   |

  Scenario: a second router is added by configuration alone
    Given the router "qa_fixed" was added touching only routers/ and config/plugins.yaml
    When the user sends "what is the time"
    Then the request for "what is the time" is sent to model "prem-1"

  # startup-only
  Scenario: an unknown router name stops the agent
    Given the agent is configured with router "defualt"
    When the agent starts
    Then the agent stops before its first loop iteration
    And the log names "defualt" and the registered routers "default" and "qa_fixed"

  Scenario: routing on without a premium model stops the agent
    Given the agent is configured with router "default" and no premium model
    When the agent starts
    Then the agent stops before its first loop iteration
    And the log names the key "premium_model"
```

### Tests and venue (which scenario goes where)

| Scenario | Venue | Why there |
|---|---|---|
| routing off / clean / keyword / tool failure / item count / agent's model kept | `Autotests/mock/test_routing_mock.py`, one pytest run per config | the rendered boundary: real loop, real hook, real router, mock provider |
| bad answers (outline) and second router | same file, config `testrouter` | needs the loop and the hook; refusal is visible only as an absent mock record |
| unknown router; no premium | `Autotests/mock/test_routing_startup_mock.py`: start the container, wait for exit or a timeout, read `docker logs` | it's about startup; no controller needed |
| the policy itself (keywords, threshold, boundaries) | `tests/router_default.metta` via `tests/mettatest.sh` (R7) | pure function, cheapest, no agent |
| A1, A8 | R3's unit test | the mock can't see a raw request (O2) |

- **"Agent's model kept" needs a way to make the agent name a model.** If nothing in
  increment 1 lets the loop name one, this scenario moves to a unit test of the hook, and
  invariant 8 is reported as covered there. The engineer says which.
- **Startup tests don't depend on log wording beyond the names.** They assert that the
  container exited (or never logged the first loop iteration within 60 s), and that the log
  contains the literal names.
